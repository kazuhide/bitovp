# 検証基盤の実利用境界を完成させる

基準は main `7be03d55ca801f1c0075791f67480bb1b35d4f78`。ユーザーの「やりきったと言えるまで」という依頼に基づき、既存の短い検証入口、全件CI、実インストール検査を維持して、今後の変更でも品質を維持できる検証基盤を完成させる。Astra の独立再評価を行った。全製品の無欠陥を宣言するための件数競争は行わない。

## 基盤全体を完成単位にする

2026-11-18 の追加指示は「小手先の修正だけで改善したと言わない」「全体をやりきってからCIと二系統レビュー」。個々の小修正をPRや最終レビューの単位にしない。以下を統合した候補を用意し、ローカルで検証してから一度の最終統合工程へ進む。失敗時の修正は原因に基づき行う。

- **変更から検証への接続**：明示したGit基点からのcommit・index・作業中・未追跡変更を集める。領域の全一致を合流し、必要な固定プロファイルと未実行の統合レーンを返す。未知・共通コード・ハーネス変更は広域へ回し、検査なしにしない。
- **主要経路の短い検証**：QCの3種に、認証/組織分離、VOD/Live登録、VOD timeline、Live lifecycle、Library render recoveryを追加する。固定された8種760件を既存runnerで実行し、任意shellや期待件数の自動追認は認めない。
- **検出力の継続検証**：tenant所有者、非冪等な開始要求の再送禁止、HDR/SDRの表示分離、子process終了までの所有権について、固定した意味上の変異を元と同じテストで検出する。実DBの取消競合対照も保持する。準備失敗、timeout、対象未到達、無関係な失敗を検出成功にしない。
- **証跡と速度**：日常の結果は高速contractの成功と残る統合検査を分ける。差分・source・policy・実行集合の同一性、完全な件数、cleanupを確認する。最終候補で8種の交互3組と統合CIを測り、既存の検出範囲を削らず時間を評価する。

正常系と競合・中断・権限違反の対応表は `docs/verification` に実行契約として残す。実DB、Redis、実メディア、インストール済みブラウザーの既存レーンを使い、日常ループへ重い処理を混ぜない。

## 受入条件と分担

1. **探索結果の完全性**：Bombadil の対照・再生で未知または無関係な違反名を捨てずに拒否する。実CLIと同じ受理関数で、混合違反・欠損・異なる再生結果を拒否する回帰を先に実行し、修正前の失敗と修正後の合格を残す。
2. **実画面の操作順**：既存の隔離インストールを使い、生成した複数操作について利用者が見る値と独立した期待値を照合する。実アプリを経由しない部品単独検査とは区別する。所有する専用ブラウザーの対象と通信制限を検証し、画面欠落・未到達・異常な通信を成功にしない。既知欠陥または限定した変異を同じ性質で検出し、再現する。
3. **実DBの取消競合**：LOCAL QC の読取後に別接続が完了を確定する順序を固定し、実POSTと条件付き更新が完了を上書きしないことを確認する。取消が先の場合の状態保持、再送、再読込、部分結果の保持も確認する。状態条件を取り除いた対照は意味上のアサーションで失敗させる。HTTP受理をOSプロセス停止の証明にはしない。
4. **依存関係の対策**：最新の一次資料と実際の依存実体で修正案を評価する。無制限時間の正規表現をMacで実行しない。対応構文の正しさと攻撃例の上限を確認できた変更だけ採用する。監査結果の除外や根拠のない脆弱性解消扱いは禁止する。未修正の上流情報とローカルの防御を明確に区別する。
5. **速度と検出力の両立**：局所検証は既存の中央値10秒以内・追加overhead1秒以内を維持する。重い実DB・実画面検査は既存の並列CIへ追加する。Web全件・skip監査・native/media・認証済み送信・DB復元・provider呼出0を保持する。自然に発見した欠陥、過去欠陥、意図的変異を別々に記録する。

## 統合

独立部分を並行実装し、対象テストと既存workflow契約テストをpush前に実行する。確定したHEAD/TREEで foreground codex-rescue と独立Codexチームを同じcmuxワークスペースに表示し、Critical/Requiredを解消する。全必須CIが合格した変更をUnreleasedとしてmainへsquash mergeし、実際のmainのtreeを照合する。本番反映・課金処理・メディア再計測は含まない。結果はObsidianへ保存し、所有する補助パネルを閉じる。
