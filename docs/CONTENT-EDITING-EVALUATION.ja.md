# クリップ編集の再現可能な評価

評価では、実際の MP4、フレーム数、音声、構図の座標、字幕と語の表示範囲を記録する。形式の検査、独立した正解との比較、人による品質レビューを区別する。単体テストの成功や追跡器自身の座標との一致を、映像の意味や被写体保持の精度として報告しない。

## 通常の作成フロー

同じエンコードの出力と AISA を読み込み、希望尺と編集方針から編集案を作る。作成した案はタイムラインでプレビューし、手直しできる。MP4 のエンコードは、編集画面で明示的に生成した時に行う。

品質評価でもこの順序を使う。案の作成だけで RenderRun や派生コンテンツが作られないこと、生成した版と保存した版が一致すること、元のコンテンツと以前の編集を保持することを確認する。

クリップの新規作成・再推論には、設定された Local LLM と実際に利用可能な GPU が必要。利用条件の詳細は [Local LLM Gateway の設定](../tools/local-semantic-gateway/README.md) を参照する。

## 比較するもの

| 層 | 記録するもの | それだけでは分からないもの |
|---|---|---|
| 入力 | 元映像と AISA の識別子・ハッシュ、元の時間軸 | 内容の正解、主役、重要場面 |
| 素材準備 | 変換条件、ツール、出力ハッシュ、fps、実尺、元映像との時間対応 | 字幕の認識率、構図の良し悪し |
| 編集 | 選択した区間、目的、モデル・プロンプト・レシピ、版 | 独立した正解に対する重要場面の採用率 |
| 実出力 | MP4 ハッシュ、全フレーム PTS、音声、表示フレーム | 物語の分かりやすさ、ネタバレの適否 |
| 人手の注釈 | 評価者、日時、対象 ID、bbox、区間、未確定箇所 | 未評価ジャンルへの一般化 |
| 性能 | 待ち時間、各工程、キャッシュ、CPU/GPU/メモリ、失敗 | 処理速度から推定した品質 |

同じ作品の解像度・別名・音声版は同一作品としてまとめ、開発用と評価用を作品単位で分ける。未見の評価結果を調整に使った場合は、その後の比較を未見の評価として数えない。未評価の品質値は null のまま保持する。

## 公開 fixture の再現

`apps/worker/scripts/evaluate-composition.ts` は、固定した開発用 fixture から MP4、contact sheet、編集文書、追跡結果、選択結果、`metrics.json` と `index.html` を作る。初回と直後の再実行を区別する。ただし OS のキャッシュ削除や DB のキャッシュヒットを保証した測定ではない。

| Scenario | 素材と目的 | 根拠の扱い |
|---|---|---|
| closeup-motion | Caminandes の頭部移動と大きさ | 同じ実フレームの手動 seed。追跡を失った範囲を記録 |
| fast-motion-cut | 走行・ジャンプ・画角変化 | 追跡できなかった範囲も保存 |
| fence-occlusion | 柵・遮蔽・再出現 | 再出現の位置を観測なしに補わない |
| multiple-subject-guard | 実映像の反転二面合成 | 意図的な合成。対象未選択の安全動作を確認 |
| actual-speech-caption | JFK の実録音と実 ASR の語時刻を別アニメーションに合成 | その映像の被写体が話したとは扱わない |

これらのシーン説明・境界・seed は手動 fixture であり、provider の AISA 解析や入力 binding を作成しない。`cropObservationCoverage` は crop と追跡器自身の観測 box の幾何学的な包含率であり、独立した正解に対する精度ではない。

開発用 fixture の再現には、必要なフィルタを含む FFmpeg、管理された日本語フォント、元映像、入力 WAV と対応する実 ASR 結果を用意する。実 ASR の `mediaSha256` を入力音声と照合し、語時刻がない segment に便宜的な時刻を追加しない。

```sh
rtk proxy sh -c 'TMPDIR=/absolute/output-root FFMPEG_PATH=/absolute/ffmpeg FFPROBE_PATH=/absolute/ffprobe pnpm --filter @bitovp/worker exec tsx scripts/evaluate-composition.ts /absolute/caminandes2-original.mp4 /absolute/output-root/evaluation /absolute/jfk.wav /absolute/asr-result.json /absolute/NotoSansCJKjp-Regular.otf'
```

これは開発用 fixture の再現用コマンド。実サービスのモデル設定・素材準備・推論・生成は、BitOVP の通常フローで検証する。

## 素材と出典

Caminandes 2: Gran Dillama は Blender Foundation の映像。出典と [CC BY 3.0](https://creativecommons.org/licenses/by/3.0/) の表示を保持し、scale、crop、縦型化、反転合成、音声の差し替えを記録する。fixture の注釈は元ファイル SHA-256 `7c0f22495d7e6d33576068af668aa887e4dfbe38690c8f6b75ae953c9df80aea` に固定され、別のエンコードへ使い回さない。変換条件と出力ハッシュは評価結果に保存する。

日本語の合成音声、実録音、アニメ、実写を区別する。リポジトリ内の Sintel と Caminandes の抜粋の出典・変換・ハッシュは、それぞれの fixture の NOTICE / README を参照する。顧客の原本、画像、文字起こし、AISA JSON、ストレージ上の名前、実行環境の秘密情報は公開リポジトリへ含めない。

## 字幕と映像の検証

1. 元映像の時間と編集後のフレームを、同じ変換規則で対応付ける。
2. 全字幕・語・カット境界について開始／終了の前後 1 フレームを列挙する。出力外のケースを先頭／末尾へ丸めない。
3. 実際の MP4 から画像を抽出し、全字幕の表示・非表示、強調、折り返し、切れを確認する。
4. 元映像と出力の PCM を比較し、書出しによる音声のずれと字幕計測の誤差を区別する。
5. 別エンジンの ASR / VAD は独立した推定として比較し、人手の正解へ格上げしない。
6. 元映像・レシピ・保存版・生成実行・成果物の対応を確認し、過去の出力との取り違えを防ぐ。

文章の表示と語の強調は別に評価する。文中の短い間に白字が残ることと、発話前に黄色の強調が始まることを同じ問題として扱わない。

## 内容と構図の評価

- 希望尺、選択尺、実 MP4 のフレーム数を区別し、不足を伸長・反復で埋めない。
- キーキャラクター、キーオブジェクト、キーモーメントを、人手の独立した注釈と比較する。
- 今後の目的別モードでは、紹介・要約などの作成目的と、ネタバレを含めない条件を別に評価する。現行の物語選定に、犯人やクライマックスを伏せる保証はない。
- 追跡の根拠が弱い区間を成功扱いにせず、全体表示と背景などの安全な構図を確認する。
- 被写体や画面内文字の欠け、話のつながり、発話途中のカット、字幕・訳の誤り、手修正量を採点する。
- 15／30／60 秒の希望尺に加え、長尺からの抽出を評価する。短い素材での成功を長編の評価へ流用しない。

品質値は注釈と実出力に結び付ける。失敗・取消・途中結果も残し、成功例だけから全コンテンツの品質を結論しない。顧客素材を使う比較の準備・記録方法は [clip-quality ツール](../tools/clip-quality/README.md) を参照する。
