# Standalone CAMBI CLI and receipt contract

This is additive: existing VMAF arguments, --version and --device-info remain unchanged.

## Commands

Capability discovery (no input/device initialization):
```
bitovp-vmaf --capabilities
```

Standalone analysis:
```
bitovp-vmaf --metric cambi --distorted PATH --output NEW_PATH --backend cpu --threads 2 --decode-threads 2
bitovp-vmaf --metric cambi --distorted PATH --output NEW_PATH --backend cuda --vendor nvidia --device 0 --threads 2 --decode-threads 2 --verify-cpu
bitovp-vmaf --metric cambi --distorted PATH --output NEW_PATH --backend vulkan --vendor amd --device 0 --threads 2 --decode-threads 2 --verify-cpu
```

--backend defaults cpu. --threads/--decode-threads default 1.
Only software decode; source dimensions and source 8/10-bit are automatically retained.
--reference, --model, --width, --height, --bit-depth, --max-frames are invalid in this mode.
--decode cpu and --inflight-frames 1 are permitted; any other value is rejected.
GPU mode REQUIRES --verify-cpu; CPU rejects it and GPU device options.
--profile is allowed, including CAMBI extractor kernel timing.
The result must not already exist. Completion is EOF, never a frame limit.

## Capability JSON (exact top-level keys)

```json
{
  "schemaVersion": 1,
  "kind": "bitovp-native-capabilities",
  "sourceSha256": "<64 lowercase hex>",
  "binarySha256": "<64 lowercase hex>",
  "officialSourceRevision": "74f930d17de8c58e7c2ce55e2b897b0030ebd8ef",
  "metrics": ["VMAF_V1", "CAMBI_NR"],
  "backends": ["cpu", "cuda", "vulkan"],
  "bandingReceiptSchemaVersion": 1
}
```

backends lists compiled backends; it does not claim an available device.
Probe selected GPU by existing unchanged --device-info and matching identities.
Old binary not recognizing --capabilities is unavailable before scoring; malformed or changed identity is an error, not fallback.


extractor.options is the COMPLETE official resolved string map generated by the pinned adapter, including defaults/unset nullable strings as "". No user-provided model or override is involved. enc_width/enc_height/enc_bitdepth are original input values; max_val is 1000, full_ref false, heatmaps_path unset, eotf bt1886. Canonical featureName is generated by libvmaf from these options, not assumed to be the model's name.
device uses the exact existing device-info.device schema. CPU mode uses null for device.
extractorKernelMs is a map and may be empty without profiling.

CPU mode: backend="cpu", device=null, requestedDeviceIndex=-1, cpuParity.checked=false, frameCount=0, maxAbsoluteError=0, and rawScore equals cpuReferenceScore (official CPU extraction).
GPU mode: backend is actual cuda/vulkan; device matches the probed GPU; cpuParity.checked=true and frameCount equals both coverage counts. Native checks every raw GPU value against its separate official CPU context before publish. Thresholding always uses cpuReferenceScore.

Timing values are relative to first decoded presentation timestamp. Positive frame duration must be supplied by decoded frame/container timing; average FPS is never substituted. PTS must be strictly increasing, no frame interval may overlap the next frame (small floating representation tolerance only). Gaps remain explicit as timeSeconds differences larger than preceding durationSeconds. Unknown duration, missing/nonmonotone PTS, source precision change or incomplete coverage are errors. Initial scope: SDR 8/10-bit, limited-range (or range-unspecified) yuv420p/yuv420p10le only, even dimensions, each 144..7680 and at least one >=216. RGB, full-range, crop/rotation and implicit pixel format conversion are unsupported.

## Failure / publication

Any invalid args/input/unsupported geometry or precision/device/CPU parity/coverage/identity/hash error returns nonzero (existing CLI exit 1), explanatory stderr, and NO successful receipt. No partial success and no fallback inside this CLI. Output uses private 0600 exclusive temporary and no-replace atomic publish. Worker decides pre-scoring AUTO availability; errors after scoring starts remain failures. Supervisor/heartbeat/admission are managed by worker's existing runner.

Worker must independently check input SHA256 + ffprobe geometry/precision/frame timing and identity, enforce exact JSON schema/coverage and original configured backend/device, and hold admission/ownership until process reaped and receipt removed.
