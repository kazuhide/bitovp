# Content Library 編集ブランチの Docker 検証環境

このブランチの編集機能を、アニメーションや合成映像と検証用 AISA メタデータで試すための環境です。Web、worker、PostgreSQL、Redis、S3 互換ストレージと閲覧用gatewayを専用の Docker Compose project で起動します。クラウドのアカウント登録や API キーは不要です。クリップの作成・編集には、設定済みのローカルLLMが必要です。

ローカルS3は1 volumeあたり128MiB・最大64 volumeとし、ストレージのメモリ上限は1GiBとし、既存の`objects` volumeは維持します。実映像の入力・準備済み素材・書き出しが増えると、ホストのディスクが空いていてもvolume数の枠が先に埋まる場合があります。Masterの未割当volume数と対象collectionの書き込み可能volumeを確認し、容量不足をDNS障害やメモリ不足と同一視せず、既存素材や成果物の削除・上書きは行わずに調査してください。

実データの大きなS3書き込みでは、512MiB制限でメモリ待ちが約84%となり、ヘルスチェックがタイムアウトしました。同じコンテナのメモリ上限だけを1GiBへ変更すると、再起動せず5秒以内に正常応答へ戻り、メモリ上限到達の増加も停止しました。この観測に基づき、previewのストレージに1GiBを割り当てます。過去のDNSエラーや再起動の原因までは、この回復だけで断定しません。

編集previewのworkerはメモリ4GiB、メモリ＋swapの合計上限も4GiBとし、追加swapは許可しません。これは別hostで動くローカルLLMのRAM予算とは別です。rendererはframeを逐次評価し、重複のない区間を条件付きでconcatします。1つのworker process内では重い編集cycleを直列化します。固定した1080×1920・30fpsの合成8構成を4GiB以内で完走し、60秒13区間は観測peak2.138GiB、180秒20区間は3.198GiBでした。任意の4K、多数の重複layerや複数worker全体の予算までを保証する測定ではありません。

## 起動

Docker と Docker Compose 2.30.0 以降、Node.js 24 以降、pnpm 11 を用意します。先に後述の「ローカルLLMで話のつながりから編集する」に従ってGatewayの接続設定を配置し、このブランチのworktreeで実行します。

```bash
pnpm preview:editing up --local-llm
```

最初の実行でイメージをビルドし、専用DBの初期設定とマイグレーションを行います。成功後に表示される URL を開いてください。標準ポートは **http://127.0.0.1:3180/library** です。

初回から別ポートを使う場合は `pnpm preview:editing up --port 3181 --local-llm` とします。一度決めたポートは設定ファイルに保存されます。

## ローカルLLMが未設定の環境

ローカルLLMの設定がない、部分的、または不正な環境では、クリップ作成・編集を無効にします。Libraryのクリップ入口を表示せず、直接の編集ページと通常の編集APIも利用できません。workerはクリップ処理を開始しません。AISAルールだけの編集へ自動で切り替えず、Claude／GPTなど外部LLMの設定も追加しません。

通常のLibrary・元映像・AISA閲覧とエンコードは利用できます。保存済みのプロジェクト・素材・字幕・キューは保持し、完成したMP4の読み取りと既存処理への取消要求は引き続き受け付けます。停止中のクリップキューの回復・取消の確定・成果物cleanupは、再設定後の通常sweepで再開します。

Libraryだけを検証する場合は、`pnpm preview:editing up`で起動できます。この操作ではクリップ編集は有効になりません。編集の検証や再開には、`--local-llm`を付けて起動します。設定の妥当性の判定はGatewayの生存確認ではありません。設定済みGatewayが停止した場合は推論エラーとして停止し、別エンジンへ自動的に切り替えません。

## エンコードから編集案を作り、プレビューして生成する

通常の入口は一つの「プロジェクトを作成」です。Libraryの「クリップを編集」から、そのencoding IDの出力映像・AISA・対応する準備済み素材を自動で読みます。希望尺を15/30/60秒、または1〜180秒の任意の長さから選び、作成を押します。素材が未準備なら通常の準備処理を進め、対応確認が必要な場合だけ同じ導線で案内します。

作成後は、選定・構図・字幕を反映したタイムラインへ直接移ります。即時プレビューで確認・修正してから、同じ画面の「生成」で縦型MP4を書き出します。編集案の作成時には書き出しジョブを作りません。構図や発話の切れ目に関する補足は、「編集の操作」の「自動編集について」から参照できます。

切り抜きを明示的に選んだ場合は、AISAの被写体位置による固定構図と左・中央・右を同じ元フレームで比較し、場面ごとに調整できます。候補の変更は未追跡区間だけに適用し、実測済みの追跡は残します。自動案で保持した座標や追跡データは削除せず、後からの編集に利用します。静止位置の提案を追跡結果とは表示しません。

新しい編集案は「全体表示＋ぼかし背景」が初期値です。自動提案や追跡結果だけでは切り抜かず、元映像全体を残します。「全体表示＋黒帯」へ変更でき、切り抜く場合は「切り抜いて画面いっぱい」を選びます。「上下に帯を設ける」は字幕用の領域を残し、字幕を消しても維持します。既存プロジェクトの構図は自動変更しません。

短い説明は項目横の「?」から開きます。選択方法や構図の詳しい条件、操作説明は折り畳みで確認できます。注釈を開くだけでは編集内容は変わりません。

保存状態は「未保存」「保存済み」を控えめに表示します。新しい編集画面では構図確認のチェックをなくし、「版を保存」「生成」を押した時に現在の案を採用します。「生成」は現在の編集内容を保存してMP4を書き出し、画面を開いたり編集したりするだけでは保存・生成を行いません。保存の競合、入力途中、実際の処理失敗は引き続き区別して表示します。

出力の自動準備は、認証済みstorageの単一MP4と、暗号化されていないVOD HLSを対象にします。DASHだけでHLS出力がない構成は初期対応の対象外です。HLSからMP4へのcopy remuxと、編集用30fpsへの素材準備は、最終的な縦型MP4の生成とは別の処理です。準備記録は元入力とAISAの一致証明に自動流用しません。

手動の素材選択・空のproject作成、以前の自動書き出し結果は追加操作として残しています。既存projectやMP4を作り直したり、同じ要求keyの結果を新ルールへ差し替えたりしません。

単語の強調には、音声認識で確認できた単語の時刻を使います。時刻が不確かな箇所は文章単位の字幕にし、注意点を進捗画面へ出します。文章を編集した場合は、その文章の古い単語時刻を解除します。発話がない音楽だけの素材では、字幕が付かない場合があります。

## ローカルLLMで話のつながりから編集する

クリップ編集は設定済みのローカルLLMを使う構成で起動します。

```bash
pnpm preview:editing up --local-llm
```

事前に [Local Semantic Gateway](../tools/local-semantic-gateway/README.md) を導入し、その接続用envを `output/editing-preview/local-semantic.env`（権限0600）、公開CA証明書を `output/editing-preview/gateway-ca.pem` へ置きます。envのCA pathはコンテナ内の `/run/bitovp-local-semantic/gateway-ca.pem` とします。必要な設定は同READMEに記載した6項目だけです。接続先は認証付きHTTPS Gatewayで、raw Ollamaを公開する必要はありません。ホスト側ファイアウォールでもDockerホストからGatewayへの接続を許可してください。

`--local-llm` はその起動操作にだけ適用します。再起動で利用するときも指定してください。通常の `up` はLLM経路とクリップ編集を有効にしません。既存のDB、元映像、編集プロジェクト、生成済みMP4、暗号化設定を保持し、workerだけに専用の外部接続ネットワークを追加します。トークンや接続用envはGitへ含めません。

管理者は「設定 → クリップ編集」（`/settings/clip-editing`）の「接続を診断」で、利用設定、編集worker、ローカルモデルの状態を分けて確認できます。画面を開いただけでは接続診断を実行しません。診断はworker経由の登録情報の確認で、モデルのロードや推論を行いません。「準備済み」はGPUの空き容量や編集内容の品質を保証するものではありません。

workerの更新記録は45秒で失効します。worker不在・初期化失敗・証明書・モデルやruntimeの版の不一致は、折り畳んだ復帰手順を参照してください。実行終了を確認できず隔離された場合は、[Gatewayの運用手順](../tools/local-semantic-gateway/README.md)で対象runtimeの停止を確認してから解除します。元の失敗記録は残り、再起動だけで成功扱いにはしません。

「クリップを編集」では、通常どおり希望尺を選んで「プロジェクトを作成」を押します。詳細設定の選択方法が「話のつながりから編集」になり、編集方針を選べます。

- **自動**：観測した内容に応じ、流れをつなぐ案か、テーマでまとめる案を作ります。
- **流れをつなぐ**：状況、変化、結果などのつながりを保ち、元映像の時間順で構成します。
- **テーマでまとめる**：共通する被写体や出来事を軸に構成します。

入力は対象encodingに対応するAISAのシーン・ショット情報と、編集用に準備したエンコード出力の音声から得た文字起こしです。字幕OFFでも、音声がある場合は話の理解に文字起こしを使います。音声認識モデルが未設定の環境ではAISAを使い、文字起こしを使えなかったことを処理結果へ記録します。解析上の除外区間を除く全ショットを分割して処理し、根拠付きの出来事の記録から編集方針を組み立てます。文字起こしと出来事の記録は同一素材・解析・モデルの範囲で再利用できます。

希望尺内に必要な出来事が収まらない場合は、結果や発話の途中を勝手に作って埋めず、編集案を作れなかった理由を返します。根拠のある内容が希望尺より短い場合は、尺を埋めるための区間を追加せず、短い編集案として残します。作成成功は物語の正しさを保証するものではありません。元映像と並ぶプレビューで、選ばれた場面、発話の切れ目、構図を比較できます。編集案の作成では最終MP4を書き出さず、プレビュー画面の「生成」で初めて書き出します。

重要対象は、選択した出来事とAISAの人物・対象記述が対応する場合に追跡へ渡します。部分一致や字幕中の名前だけを座標の根拠にしません。対応が曖昧な場面、複数の重要対象が縦画面に入らない場面、追跡を失った区間では全体表示で対象を残します。構図を手動で調整すると、その変更は利用者の編集として保存されます。

日本語訳の既定は、原語字幕に場面情報と既訳を添えて処理するQwen翻訳です。別の翻訳モデルを使う場合は、[Gatewayの導入手順](../tools/local-semantic-gateway/README.md)で実モデルと専用runtimeを用意します。PLaMo用の公開manifestを権限0600で `output/editing-preview/local-caption-manifest.json` に配置し、既存の接続envへ次を追加します。

```dotenv
BITOVP_LOCAL_CAPTION_PROVIDER=PLAMO
BITOVP_LOCAL_CAPTION_MANIFEST_FILE=/run/bitovp-local-semantic/local-caption-manifest.json
```

PLaMoの利用条件を満たし、実際の重み・runtimeのhashを記録したmanifestを使用してください。previewの起動前に共通schemaで検証し、Webとworkerへ読み取り専用で渡します。不足や不一致でQwenへ自動的に戻しません。この設定の検証はモデル本体の導入・推論や翻訳品質の検証とは別です。設定を追加しなければ既存のQwen経路を使います。

初回は全文の文字起こしと各分割入力の推論があるため、通常の自動選定より時間がかかります。モデルは固定した同一digestをAMDまたはNVIDIAのprofileで実行します。profileの変更後は `--local-llm` 付きで再起動してください。

Codex CLIをアプリの実行依存にする旧構成は撤回したままです。新しいローカルLLM経路はその構成と別のもので、Codex、Claude、SSH接続をアプリから呼び出しません。保存済みの旧プロジェクトも、ローカルLLMを設定した環境で引き続き閲覧・編集・生成できます。

## 元映像と編集結果を比較して切り抜きを調整する

プレビューでは「元映像」と「編集結果」を同時に表示します。広い画面では左右、狭い画面では上下に並び、編集結果の外枠も出力の縦横比に合わせます。再生・音声・再生位置は共通です。元映像の枠は、実際に切り抜く範囲を示します。

一時停止し、元映像の準備ができたら、枠内をドラッグして位置を、四隅で大きさを調整します。操作中は結果とタイムラインへ即座に反映し、指を離すと1操作として確定します。Undoでその操作全体を戻せます。Escやpointer cancelでは元へ戻り、操作中の案は保存・生成しません。枠や四隅は矢印キーでも調整でき、Shiftで大きく動かせます。

未追跡範囲を選択した場合は、その場面の固定構図を調整します。追跡範囲では、場面内の既存の構図点へ同じ位置補正・拡大率を適用し、点の数・時刻・補間方法と区間の境界は保持します。前者は追跡範囲、後者は未追跡範囲を変更しません。素材の端や他の構図点に合わせて調整可能な範囲を制限します。字幕帯がある場合は実際の主映像枠で比較します。

明示的な全体表示や、一部の合成クリップでは枠の確認のみができます。切り抜き方法は既存の「映像」設定から調整してください。構図候補の選択と直接操作は同じ保存・明示生成の流れを使い、画面上の操作だけでMP4を書き出すことはありません。

## アニメーションでショット別の構図を試す

起動後、次のコマンドで「Caminandes 2：アニメの縦型構図デモ」を追加できます。初回はホスト側で公式配布の47 MBの映像を取得し、サイズとSHA256を照合します。アプリの内部ネットワークは外部へ開きません。

```bash
pnpm preview:editing demo
```

原本00:09〜00:39の30秒を1280×720・固定30fpsに変換した映像です。左側の小さなラマ、顔のアップ、全身、植物への切替があり、元映像と縦型の切り出し位置・大きさを比較できます。シーンと被写体の囲み座標は映像を見て作成した検証用メタデータです。実AISAの解析サービスは実行していません。

Libraryのサンプルから「クリップを編集」を開き、アニメ用の保存先 `Editing preview local S3 (licensed animation demo)` と `bitovp-editing-preview` を選びます。以降は下の合成サンプルと同じ素材準備・プロジェクト作成の流れです。構図を提案する時は元映像との対応を確認します。被写体の囲み座標があるショットは、その大きさから縦型の構図を提案します。中心点だけの解析は従来の固定サイズを使い、囲み全体を縦型に収められない場合は全体表示になります。

「構図の区間」で対象を切り替え、「切り出しの拡大率」と中心位置を調整できます。中心を動かしても現在の大きさを保ちます。従来の編集画面はショットごとの固定値です。後述の拡張編集では、構図の記録点と実映像を使う追跡も試せます。

再実行は追加済みのサンプルとユーザーの編集を上書きしません。既存の合成サンプルも残します。保存した元ファイルのhashが変わっていれば、上書きせず停止します。

素材: [Caminandes 2: Gran Dillama — Blender Foundation](https://video.blender.org/w/x3QKwgFXGZQ7yvCTD2wHJA)、[CC BY 3.0](https://creativecommons.org/licenses/by/3.0/)。作品内creditでライセンスを確認しています。このデモでは30秒の抜粋、24→30fps・1280×720への変換、縦型cropを行います。原本の色metadataが未記載のため、デモ用にBT.709と仮定して変換・出力します。共有時の帰属表示にも作品名・配布元・ライセンス・変更内容を添えてください。詳細な出典とshot時刻は `apps/worker/src/library-editing/animation-demo.json` にあります。

## 会話のあるアニメで字幕を試す

Libraryのトップは元コンテンツを表示します。作品の「クリップ案」から、同じ作品で作った複数の編集案を開けます。各案の尺・形式・書き出し状況を確認でき、最新の書き出しが失敗しても以前の成功動画を開けます。「別のクリップを作成」は新しい案を作り、既存の案を上書きしません。派生動画の詳細から元作品と編集案へ戻れます。

```bash
pnpm preview:editing dialogue
pnpm preview:editing asr --local-llm
```

音声認識はローカルのwhisper.cppで行い、ローカルLLMはその台詞とAISAを使って場面を選びます。字幕の台詞をLLMに創作させることはしません。実測単語がある字幕は選んだ範囲の単語から短い読み単位に分割し、単語時刻がない場合は元の文字起こしと区間を保持します。

従来の多言語 `base` に加え、多言語 `small` を選べます。明示的なセットアップ時だけ公式配布の固定版を取得し、サイズとSHA-256を検証します。モデル選択は専用preview設定に保存し、WebとWorkerへ同じモデルSHAを渡します。既存の認識結果・クリップ・出力動画は保持します。

```bash
# ローカルLLMを接続したpreviewで認識モデルを変更する
pnpm preview:editing asr --model small --local-llm

# 従来の認識モデルへ戻す
pnpm preview:editing asr --model base --local-llm
```

LLMを接続しないLibrary閲覧用previewでは `--local-llm` を外せますが、クリップ編集は無効です。`small` は487,601,967バイト（約465MiB）で、CPU処理では `base` より時間・メモリが増えます。モデル変更後の認識精度は素材ごとに検証してください。認識の再作成は別の証拠として保存され、既存編集の字幕を自動で置き換えません。配布元と固定SHAの根拠は[公式モデルファイル](https://huggingface.co/ggerganov/whisper.cpp/blob/5359861c739e955e79d9a303bcbc70fb988958b1/ggml-small.bin)です。

「Sintel：会話と字幕のデモ」がLibraryに追加されます。Blender公式トレーラーの12〜26秒を抜粋し、固定30fpsへ準備した14秒の映像です。リポジトリに含む約2MBの検証済みファイルを読み取り専用で取り込みます。シーンと被写体の座標は手作りの `FIXTURE_AUTHORED` です。既存のサンプルや編集は上書きしません。

素材の準備と解析の対応付けは済んでいます。この手作り素材は「素材の操作・手動編集」からプロジェクトを作り、タイムラインで確認できます。エンコードIDからの自動字幕付き編集案は、後述の実BBB・実写Tears of Steelで試してください。指定尺より短い素材を繰り返して埋めることはありません。単語の時刻が確認できた発話は強調字幕、不確かな発話は文章単位の字幕になります。音楽だけの長い区間では音声認識が存在しない発話を生成する場合があるため、書き出し前に字幕の文章と時刻を確認します。

素材: [Sintel — Blender Foundation](https://durian.blender.org/sharing/)、[CC BY 3.0](https://creativecommons.org/licenses/by/3.0/)。抜粋、24→30fpsへの変換、SARとBT.709色情報の明示を行っています。原本の色情報は未記載のため、BT.709はデモでの仮定です。帰属表示とファイルの識別情報は `apps/worker/src/library-editing/fixtures/sintel-dialogue-NOTICE.md` にあります。

## ショットの選定と素材の対応

通常の入口は「プロジェクトを作成」です。encodingの出力映像とAISAから編集案を作り、タイムラインで確認・修正してから「生成」でMP4を書き出します。手作りサンプルなどencodingと関連付いていない素材では、「素材の操作・手動編集」から素材を準備し、手動のプロジェクトを作成できます。

希望尺は1〜180秒で、15／30／60秒のボタンも使えます。原本順で隣接するショットのまとまりから、指定以内で最も近い長さを選びます。例えば12秒の指定で11秒程度になる場合があります。映像の繰り返し、黒画面の追加、ショット途中の切断では尺を埋めません。収まるまとまりがない場合は、希望尺を増やすか手動編集へ進みます。

通常の未準備の映像は、encodingの出力から素材と保存先を解決して準備を進めます。選んだ解析・希望尺・追加設定を保ったまま、その素材の準備完了を待ちます。映像と解析の対応が未確認なら、同じ導線で内容・時刻・画角を確認して保存し、明示的に編集案の作成を続けます。

準備要求の応答が途切れた場合は、自動で準備を重複実行しません。素材一覧へ戻り、準備状況を確認して使用する素材を選んでください。編集案の作成要求の応答が途切れた場合は、表示される同じ要求の確認を使います。待機をやめても受け付け済みの作成は続く場合があり、判明した受付結果を開くか進捗画面で処理を取り消せます。

手作りサンプルを別の素材版として準備した場合は、アニメの `pnpm preview:editing demo`、合成サンプルの `pnpm preview:editing seed` を再実行すると、固定素材と手作りメタデータの対応証拠を追加します。既存の映像・編集・成果物は上書きしません。

自動採用には、素材hash、解析版と内容のhash、時間写像、幾何などの対応証拠が必要です。コンテンツ名や秒数が同じだけの過去解析を、自動的に確認済みにはしません。今回のサンプルの証拠は `FIXTURE_AUTHORED` であり、実AISAの解析根拠とは区別します。対応証拠は準備済み素材を変更せず、専用の追記専用DBレコードに保存します。

既存のアニメ用サンプルでは、初回DB保存時に一部のショット時刻の末尾桁が丸められています。この既知の保存形式も、作成時のhashと保存済みraw・正規化JSON全体のhashの組合せが一致する場合だけ受け入れます。既存のメタデータや編集は書き換えず、一般の解析の照合に数値許容差は追加しません。

旧版の固定cropとFITによる編集・書き出し結果も保持します。通常の編集案では「字幕・構図・場面の設定」から内容による選定、追跡、字幕の設定を変えられます。応答が途切れた時は、同じ入力のまま同じ受付結果を確認します。

## 字幕・追跡・複数形式で生成する

初回だけ次を実行すると、約148MBの音声認識モデルをホスト側で取得・SHA256照合し、workerを再起動します。モデルは読み取り専用でマウントします。認識中に外部サービスへ音声を送信しません。

```bash
pnpm preview:editing asr --local-llm
```

「プロジェクトを作成」の追加設定で、希望の内容、まとまり優先／長さ優先、形式、候補数、被写体追跡、字幕、日本語／英語／自動判定を選べます。内容を指定すると、シーンとショットの説明を使い、できるだけ同じ場面のまとまりを選びます。3候補は縦型・横型・正方形の編集可能なプロジェクトです。長さ優先では内容の入力を使いません。

字幕を有効にすると、候補の前後を含む音声を認識し、発話途中の始まり・終わりを避けるようショットを選び直します。選び直した区間から字幕と追跡を作るため、時刻もその区間に対応します。安全な区切りが見つからなければ、観測した発話の証拠を保存し、確認が必要な編集案として表示します。音声認識が使えない場合や素材の端で発話の完結を判断できない場合も、注意点を表示し、場面情報による候補を使います。発話や物語の完結を保証する機能ではありません。

進捗画面では素材の準備、選定、文字起こし、発話の切れ目の確認、追跡、プロジェクト作成を表示します。作成後は同じプロジェクトの編集画面を開き、すぐにプレビューできます。MP4の書き出しは内容を確認した後の「生成」で開始します。取消と失敗後の再試行もできます。同じ要求キーは受付結果を再利用します。再試行は前の履歴を残して新しい処理を作ります。

未確認の素材と解析の組合せは、映像・時刻・画角を確認してから対応を保存します。確認者による記録は `EDITOR_ATTESTED`、サンプルの手作り解析は `FIXTURE_AUTHORED`、固定入力・公式API取り込みによる記録は `CAPTURED_INPUT` と区別します。実BBBと実写Tears of Steelは、承認済みのCLI接続で既存の出力とAISA原本を取得し、通常経路で取り込みました。過去の出力をCAPTURED_INPUTへ格上げしていません。追加の有償評価ジョブは、承認された上限と非公開の実行台帳で別途管理します。サンプルの起動や案の作成でBitmovinの課金エンコードを自動投入しません。

## 拡張タイムラインの操作

新しい編集案はこのタイムラインで直接開きます。旧版の手動編集を拡張する場合は、保存してから「レイヤー・字幕・音楽の編集を開く」を押します。元の不変の版とMP4は残り、新しい下書きで編集を続けます。

- タイムラインはクリックで移動、ズーム、ドラッグで配置・両端のトリムができます。端の矢印キーは1フレーム、Shift併用は1秒です。数値はEnterまたはフォーカスを外して確定します。
- 「映像」で編集用に準備した別素材を追加し、小窓として重ねられます。配置、透明度、前のクリップとのクロスフェードも設定できます。
- 構図の位置・拡大率を変え、「この再生位置の構図を記録」を複数箇所で押すと、その間を補間します。追跡を失った区間の表示は、選んだ映像の収め方と固定構図候補に従います。
- 「音声」で元音声の消音、音量、フェード、素材からの追加音声、字幕中の音楽低減を設定できます。字幕連動は64字幕までで、時刻の変更・削除にも追従します。従来保存した固定の音量低減区間は保持します。
- 「字幕」で文章、時刻、単語の強調時刻、文字色・強調色、タイトル、PNG画像を編集できます。画像は8MiB・2048×2048までの非アニメーション8bit PNGです。
- プレビューは現在の下書きを即時に反映します。「生成」は現在の内容を保存・版固定してMP4を書き出します。下書きや版を個別に保存する操作も残しており、生成後の手直しも同じプロジェクトで続けられます。

保存の応答が途切れた場合など、サーバーに新しい下書きがあると「保存済みの下書きを読み直す」を表示します。読み直す前の編集内容も「元に戻す」に残ります。

映像素材の準備は、回転なし・正方画素・SDRのH.264／8bit HEVC MP4・MOV、固定24／25／29.97／30fpsに対応します。既に対応する30fps素材は元のbytesを保ちます。他の対応fpsは、実フレームの対応表と検証記録を持つ30fps素材へ準備します。HDRや可変fpsはこの編集profileの対象外です。

## 合成サンプルで手動編集を試す

Library の「AISA編集サンプル：3つの合成シーン」を開きます。映像は18秒、960×540、固定30fpsのH.264 MP4です。0〜6秒は左の緑マーカー、6〜12秒は右のオレンジマーカー、12〜18秒は中央の青マーカーを目印にできます。AISA形式のメタデータはこの検証用に作成したもので、実際の解析サービスの出力ではありません。

1. 「クリップを編集」を開きます。
2. 「出力フォルダーを選択」で `Editing preview local S3 (synthetic only)` と `bitovp-editing-preview` を選び、現在の場所を保存先にします。
3. 「編集用素材を準備」を押し、準備完了を待ちます。
4. 形式を「縦型 9:16」、シーン解析をサンプルの日本語解析にして、プロジェクトを作成します。
5. AISAの候補から区間を追加するか、手動で区間を編集します。保存済み解析の時間軸や構図を元映像で確認してから、提案を確定してください。
6. 編集プレビューで現在の区間順・構図・音声を確認します。タイムラインをクリックするとその位置へ移動し、ズームや区間端のハンドルで尺を調整できます。数値入力も使えます。ドラッグの変更は指を離した時に確定し、Escapeで取り消せます。
7. 「下書きを保存」して再読込し、編集が残ることを確かめます。
8. 「版を保存」で編集を残せます。「生成」でMP4を書き出し、ダウンロードやLibraryの派生作品を開きます。

タイムラインの時刻は出力映像の位置です。「編集プレビュー」は未保存の編集をその場で表示します。「出力プレビュー」は保存した版から生成したファイルです。現在の編集と異なる場合は注記を表示します。元映像とAISA構図を比較する時は「元映像とAISAの構図を確認」を開きます。

### 編集プレビューと区間操作

- 映像または「編集を再生」を押すと、選んだ区間を順に再生します。前後1フレーム・先頭・末尾への移動、0.5／1／2倍、繰り返し再生も使えます。
- 初期状態は消音です。音声を有効にしても、区間の音声設定が「無音」ならその区間は鳴りません。
- 映像にフォーカスを置いた状態で、Spaceは再生・停止、左右キーは1フレーム移動、Home／Endは先頭・末尾へ移動します。
- 「編集する区間」で選んだ区間の設定を表示します。「再生位置で分割」は再生ヘッドのある区間に、「選択区間を前へ／後ろへ／削除」は編集対象の区間に作用します。操作を間違えた時は「元に戻す」を使えます。
- 数値欄に未適用の変更がある場合は、適用または取消してから別の区間へ切り替えます。再生位置を動かしても未適用の入力は残します。

従来の編集画面は単一素材向けです。「レイヤー・字幕・音楽の編集を開く」で、後述の拡張編集へ移れます。正式な生成ファイルは、人が確定した版または対応証拠を検証して自動採用した不変の版から作成します。

## 停止と再起動

```bash
pnpm preview:editing status
pnpm preview:editing logs
pnpm preview:editing stop
pnpm preview:editing up --local-llm
```

`stop` はコンテナを停止します。`down` はこの専用projectのコンテナとネットワークを除去します。どちらもDB、元映像、生成した映像を保存するvolumeを残します。次の `up` は変更したソースを再ビルドし、同じデータで再開します。再seedは既存のサンプルやユーザーの編集を上書きしません。

```bash
pnpm preview:editing down
pnpm preview:editing url
```

## 環境の保存場所と範囲

専用project名にはworktreeのパスから生成した識別子が付きます。設定と生成した認証情報は `output/editing-preview/` に保存し、GitとDockerのビルド対象から除外します。このフォルダーを移動・削除すると、保存済みDB内の暗号化情報や接続先を再利用できなくなるため、データを残す間は一緒に保管してください。

通常構成で公開するのは閲覧用gatewayのlocalhostポートだけです。gatewayは固定のWebサービスへ転送し、アプリやDBの資格情報を持ちません。通常のWeb、worker、DB、ストレージは内部ネットワークだけに接続します。サインインを省略したローカル検証用のため、外部公開には使いません。DB管理権限は初期設定ジョブだけが持ち、Webとworkerは制限付きのDBロールを使います。既存のリポジトリ `.env` やシェルのクラウド認証情報を読み込みません。物語選定の実験を明示的に有効にした場合だけ、前述の専用設定とWorkerの追加ネットワークを使います。

通常構成はアプリの内部ネットワークから外部サービスへ接続しません。`--local-llm` では前述のGateway接続だけを追加します。実際のBitmovin/AISA解析や外部ストレージを使う試験は、この環境の対象外です。編集は固定30fps、最大20区間・180秒です。拡張編集は素材8点、映像4レイヤー、音楽8トラックまで使えます。

## 起動に失敗した場合

`pnpm preview:editing logs` と `pnpm preview:editing status` を確認してください。Dockerが起動していない場合は、起動後に再度 `up` を実行します。ポート競合は、初回設定前に `--port` で回避できます。既存設定がある状態では、helperはポートや認証情報を勝手に作り直しません。

ビルドはインターネットから固定したイメージやパッケージを取得します。起動後の合成サンプルによる編集・生成は、専用Docker環境内で動作します。


## 映像の収め方と字幕の配置

プロジェクト作成時の詳細設定で、映像の収め方と字幕の配置を別々に選べます。編集画面でも変更し、保存・再読込・Undoで元に戻せます。新しい通常の編集案は「全体表示＋ぼかし背景」と「映像に重ねる」が初期値です。既存の編集案は保存済みの構図を維持します。

- **全体表示＋ぼかし背景**：元映像を切り抜かず、上下または左右の余白を同じ映像のぼかし背景で埋めます。通常保存や「生成」での採用だけでは切り抜きに変わりません。
- **全体表示＋黒帯**：元映像を切り抜かず、余白を黒で残します。
- **切り抜いて画面いっぱい**：明示的に切り抜きを選び、追跡できた構図や固定構図の候補を使います。未追跡区間の位置・大きさは、場面ごとの候補や元映像の枠から調整できます。
- **映像に重ねる**：字幕に背景を付けて映像上へ表示します。「字幕の背景色」「字幕背景の濃さ（%）」で調整できます。
- **上下に帯を設ける**：主映像の上下に各18%の帯を確保し、字幕を下帯へ配置します。映像を縦につぶさずに構図を再計算します。帯は字幕を削除しても残ります。「映像に重ねる」で解除できます。

「選択方法」の i はマウスオーバー、キーボードのフォーカス、クリック・タップで説明を開きます。「シーンのつながりを優先」は同一シーンの連続ショットが全体の最長案の80%以上なら採用し、不足するとシーンをまたぐ案を使います。「ショット単位で希望尺に近づける」は希望尺を超えない最長の隣接ショット区間を選びます。同尺ではシーン切替が少なく、開始が早い案を優先します。自動字幕の発話境界や除外条件によって案が変わるため、タイムラインの注意も確認してください。
