# VOD入力タイムライン：空白への移動と端の伸縮

## 再現と原因

個別編集の本体ドラッグも、クリップ中心が他のクリップ中心を越えた場合の並べ替えだけを実行していた。同じ順序のまま開始時刻を動かす操作がなく、空白のあるタイムラインではドラッグしても動かない。

端のハンドルは選択中だけ表示されるため、別トラックのクリップを選んだ状態から端をつかみにくい。使用開始が0秒の素材は左へ伸ばせないが、その理由も操作面で伝わらなかった。

## 修正する操作

- V1/A1を個別にした本体ドラッグは、素材のin/out・長さを保った開始時刻の移動とする。反対側のトラックとプログラム全体尺は保つ。
- 移動は0〜全体尺−クリップ長に収める。同じトラックの重なりは、既存の独立トリム／差し替えと同じ上書きとしてステージ表示する。影響する区間だけを切り分け、区間外の元の素材時刻を保つ。離したときに一度確定し、Undoでまとめて戻せる。
- 連動するAVペアの本体ドラッグと、前へ／後へ・Alt＋左右による並べ替えは維持する。
- 本体ドラッグでは開始端と終了端の両方をスナップ候補にする。画面上8pxで吸着、12pxまで維持。Alt／Optionで解除でき、実ポインター位置から距離を判定する。
- クリックと移動を区別する小さな開始距離を設ける。途中で元の位置へ戻しても誤ってシークしない。キャンセル、外部更新、権限変更、スクロール、フォーカスの扱いを維持する。
- 元素材に残る範囲とタイムラインの範囲で端の伸縮を止める。開始0秒では左へ伸ばさず、全体移動との違いをハンドルの短い注釈で示す。引き延ばし・フレームの捏造は行わない。
- 十分な表示幅があるクリップでは、未選択でもホバーで端を示し、そのままつかんで選択・伸縮できるようにする。キーボードではクリップを選んだ後に端へ移れる。

## 共通モデル

`positionVodInputTimelineClip(document, {track, id, startMs}, nextId)` を追加する。既存の並べ替えAPIとは区別し、同じV2形式を返す。素材範囲は変えず、範囲・ID・クリップ数・空白などの検証を通す。ワイヤー形式・DB・認証・既存リクエストのhashは変更しない。

画像同等の配置では、音声を左へ動かした後の中間空白が11.658秒になる。ネイティブAPIのPaddingSequenceは1個につき最大10秒で、各素材のpaddingBefore/paddingAfterを独立して指定できる。そのため、中間空白は最大20秒までを前の素材のafterと次の素材のbeforeへ分配する。10秒以下は既存のbeforeだけのgraphを維持する。先頭・末尾は10秒までのままとし、source auditionの自然尺例外も維持する。プレビューの窓が中間空白の途中から始まる場合も、全体の配置に基づいて検証する。

公開SDK 1.287.0の[PaddingSequence](https://github.com/bitmovin/bitmovin-api-sdk-javascript/blob/v1.287.0/src/models/PaddingSequence.ts)と[ConcatenationInputConfiguration](https://github.com/bitmovin/bitmovin-api-sdk-javascript/blob/v1.287.0/src/models/ConcatenationInputConfiguration.ts)を根拠とする。ローカルの実FFmpegで11.658秒・20秒の中間空白、空白内だけのプレビュー、両トラックの復帰、反対側の映像bytes不変を検証し、同じdocumentのnative graphも生成・serializeした。今回、課金APIによる最終出力の受理は実行しない。

## 操作の区別

| 操作 | 結果 |
|---|---|
| 個別クリップの中央をドラッグ | 尺を保ってそのトラックだけ位置を移す。重なった同一トラック区間は上書き |
| 個別クリップの端をドラッグ | 素材の余りを使って区間を伸縮。反対側と全体尺は固定 |
| リンクしたAVペアをドラッグ | 既存の並べ替え |
| 4px未満の本体操作 | クリックとして選択・シーク |
| Escape | ドラッグ途中の編集を破棄 |

本体の移動は整数msで行い、素材のin/outを変えない。トリミングは従来のフレーム単位を使い、境界へ吸着した場合はその正確な整数msを優先する。選択外の端は幅32px以上でホバー表示し、極小クリップの本体をハンドルで覆い尽くさない。

## 受け入れ条件

1. 画像同等の空白を持つV1/A1で、クリップ本体を左へ動かせる。長さ・in/out・反対側が変わらない。
2. 素材に余りがあれば左端を伸ばし、開始0秒ならそこで止まる。未選択クリップの端も直接つかめる。
3. 開始／終了の両端吸着、Alt／Option、クリック、Escape、Undo、リンク編集と並べ替えの回帰を確認する。
4. 実DockerでプレビューMP4と実画面を検証する。日本語の説明を常時増やさず、狭い画面にも対応する。
5. 同じcmux内でCodex RescueとAgentチームのレビューを並列表示し、指摘を修正する。CIと最終HEADを確認してDraft PRへ反映する。

同じブランチのUnreleasedとして開発する。mainへのマージ、リリース、版番号変更、本番配備、課金エンコードは行わない。
